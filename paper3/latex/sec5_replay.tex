\section{Independent replay}
\label{sec:replay}
\begingroup\sloppy

The repository holds no saved output of the axiom check for the family,
no automated build of its Lean, and \texttt{enable\_nanoda: false} in the
comparator's settings (Section~\ref{sec:proof}). We therefore built the
proof ourselves, in isolation, at the Lean version the repository pins,
and recorded what the kernel reports. This section says exactly what was
run, where, and what came out. The scripts are quoted verbatim in
\repofile{paper3/replay/README.md}, and the logs are under
\repofile{paper3/replay/logs/}.

\subsection{What was run, and where}

A fresh copy of the clone (commit \texttt{4eaee875}) was built inside a
sandbox on the project's machine. The sandbox tool is \texttt{bwrap}
(bubblewrap). Inside it, the system directories are read-only. The home
directory is a private, empty one (a \texttt{tmpfs}, a scratch file
system held in memory and gone when the sandbox ends), so nothing of the
real home or of this repository is visible. Processes, inter-process
communication and host names are kept apart from the host's (separate
``namespaces''). The whole sandbox is confined to eight cores
(\texttt{taskset -c 0-7}) at the lowest scheduling priority. And the
network is on, because the repository's build file
(its \texttt{lakefile}) clones its 42 dependencies (the packages of its manifest, Section~\ref{sec:proof}) at build time and the compiled Mathlib comes
from a download cache. Inside the sandbox, the Lean installer
\texttt{elan} was installed into the private home and fetched the
pinned Lean version from the repository's own \texttt{lean-toolchain}
file. Then, in the clone's \texttt{lean/} directory, three commands
ran. The first, \texttt{lake exe cache get}, downloads the compiled Mathlib.
The second, \texttt{lake build OAI.Algorithms.SubexponentialSAT.Main}, builds
the solution's 3,091 files. It does not build the collection's default target,
which would build the whole collection (its \clonefile{README.md}, line 16, counts 721 manuscripts in 373 families). The third is \texttt{\#print axioms} of the
one theorem the comparator names,
\path{OAI.Algorithms.SubexponentialSAT.SqrtLogSpace.exact_count_and_sat},
through \texttt{lake env lean}. Only text left the sandbox; nothing
built inside it was executed outside it.

Two runs were needed. The first, started at 01:03 on 2026-11-05, failed
at once at the build step. Its command line carried
\texttt{-j 8}, an option this version of the build tool does not have.
The whole of its build log is the one line \texttt{error: unknown short
option '-j'}, and nothing of the family was compiled. The second, started
at 01:16 with that option removed and the core cap moved to
\texttt{taskset}, is the run reported below. Both scripts, both
versions, and the launch command are in the README; the first run's
logs are kept beside the second's.

\subsection{What came out}

The build finished with exit code~0 in 33~minutes of wall clock on
eight cores (01:16:25 to 01:49:31). It compiled \textbf{3,091} modules
with the prefix \texttt{OAI.Algorithms.SubexponentialSAT}: exactly the
set the inspection of Section~\ref{sec:proof} enumerated, the same
3,091 names with nothing missing on either side
(\repofile{paper3/replay/counts.sh}). The build tool's own job total,
\texttt{12014}, counts the cached Mathlib and dependency modules as
well, none of which was compiled. The log has no line containing
\texttt{error} and none containing \texttt{sorry}. Its eleven
\texttt{warning} lines are the build tool noting that the repository's
compatibility patches leave eleven dependencies with ``local changes'',
and none of the eleven is Mathlib.

Eight source files of the closure carry nineteen \texttt{\#print
axioms} commands (seventeen files of the family's directory do, but
nine of those are never built), so the build log records nineteen
axiom lines as it goes. Every one reads
\texttt{[propext, Classical.choice, Quot.sound]}, the three standard
axioms. Among them, \clonefile{SqrtLogSpace/Final.lean}, lines 197--201,
prints the axioms of \texttt{compiled\_exact\_count\_and\_sat},
\texttt{exact\_count\_and\_sat}, \texttt{exact\_count\_eth},
\texttt{sat\_polynomial\_space} and \texttt{original\_sat\_main}. The
separate \texttt{\#print axioms} run after the build gives, for the
comparator's theorem,
\begin{quote}\small
\path{'OAI.Algorithms.SubexponentialSAT.SqrtLogSpace.exact_count_and_sat'}\\
\texttt{depends on axioms: [propext, Classical.choice, Quot.sound]}
\end{quote}
(\repofile{paper3/replay/logs/run2/axioms.txt}). The versions are Lean 4.34.1 (the log line reads \texttt{Lean (version
4.34.1, commit 5045d005…, Release)}), Lake \texttt{5.0.0-src+5045d00},
and Mathlib at revision \path{d13f23b723b8a846827a245b89c10fc7d3f11612}
from the clone's own manifest, with its compiled files from the Mathlib cache (8,908 files).
The replay copy is at commit \texttt{4eaee875}, the same as the pristine
clone. The comparator file and the solution's files have the same
hashes in both (\repofile{paper3/replay/logs/run2/hashes.txt}). A hash here is a SHA-256, a fingerprint of a file's bytes that two different files do not share in practice; the
comparator statement's begins \texttt{4183b205}. The full build
log is kept out of the repository by size; its SHA-256
(\texttt{d313f594…}) and its last 200 lines are committed.

So the sentence every later section relies on reads: \emph{replayed}.
The solution builds from source at the pinned Lean version with
unpatched Mathlib, and the kernel reports the three standard axioms and
nothing else for the theorem the comparator names. This moves the first
three items of the inspection's trust boundary (Section~\ref{sec:proof}):
the build is no longer OpenAI's unpublished one, the axiom output is now
on record, and the Mathlib revision was fetched from upstream and not
patched.

\subsection{The second checker}

The comparator's settings for the family have \texttt{enable\_nanoda:
false}: OpenAI's check of this family ran the Lean kernel only. We ran a
second checker, in the same sandbox, after the build
(\repofile{paper3/replay/nanoda.sh}, recorded in the README before it
ran). Two tools are involved. The first is \texttt{lean4export} (tag
\texttt{v4.34.0}, commit \texttt{076e8e57}), built with the pinned
\texttt{v4.34.1} Lean so that it reads the compiled files the build
produced. It wrote out \texttt{exact\_count\_and\_sat} and everything it
depends on from the built environment, as a plain-text file. That file is
2,355,666,449 bytes and 43,633,742 lines, in format version 3.1.0, and took
68~seconds to write. The second is \texttt{nanoda\_lib} \citep{Nanoda} (version 0.4.31,
commit \texttt{8de7e0c4}, 2026-10-29), a checker for Lean~4 proofs
written in Rust that shares no code with the Lean kernel. It read that
file and re-checked every declaration in it. The permitted axioms were \texttt{propext},
\texttt{Classical.choice} and \texttt{Quot.sound}, and the \texttt{Nat} and \texttt{String} literal extensions were on.
Its output (\repofile{paper3/replay/logs/nanoda/nanoda_check.txt}):
\begin{quote}
\texttt{Checked 95176 declarations with no errors}
\end{quote}
in 110~seconds on eight cores, exit code~0, after printing back the
theorem's statement and the three axioms from its own reading of the
file. The export contains exactly three \texttt{axiom} declarations
(\texttt{grep -c '"axiom"'} on the file), so nothing else could have
been permitted. The export file (SHA-256 \texttt{bdbc9afe…},
\repofile{paper3/replay/logs/nanoda/export_sha256.txt}) stays in the
sandbox directory by size; the configuration, the build logs and the
checker's output are committed.

\subsection{What this does not claim}

\begin{itemize}
\item The replay trusts the Lean kernel of the pinned version
  (\texttt{v4.34.1}) and upstream Mathlib at the pinned revision. It
  moves the proof's trust from ``OpenAI's unpublished build'' to ``a
  build we ran'', not from the Lean kernel to anything else. The second
  checker removes the Lean kernel from the list for the theorem's
  dependencies as exported, but adds \texttt{lean4export} (that it
  writes out what the environment holds) and \texttt{nanoda\_lib} (that
  it checks what it reads) to it. Two independent checkers agreeing is
  evidence, not a proof that either is correct.
\item It is not the comparator run. The comparator checks that the
  solution's exported statement matches the challenge's. We did not run
  that tool chain. The statement-level match the paper relies on is
  the textual one of Section~\ref{sec:proof}: the 35 definitions and the
  theorem statement, identical after normalising spacing, two of them up
  to the \texttt{noncomputable} keyword.
\item The counts above are counts of lines in one build's log on one
  machine with the named versions; a different build tool would print
  different job totals (the 12,014 includes the cached Mathlib modules),
  and a different machine a different time.
\item Nothing here bears on what the theorem \emph{says}
  (Section~\ref{sec:statement}) or on the manuscript's unverified
  exponents (Section~\ref{sec:beyond}); a replayed proof of a weak bound
  is a replayed proof of a weak bound.
\end{itemize}
